12 Phân quyền chức năng theo nhóm (Group-based Feature Authorization) Hoàn thành
Bối cảnh & Quyết định thiết kế

Trước đây UI kiểm soát theo role cứng (7 role). Yêu cầu mới: admin tạo nhóm linh hoạt, gán user, gán feature — nhóm quyết định UI thấy gì. Backend RBAC (deps.py) không đổi — feature chỉ ẩn UI, không bypass API protection.

Tại sao dùng static feature codes thay vì dynamic?
Lựa chọnƯuNhược
Static codes trong features.py (đã chọn)Không mất sync giữa DB và code; typo bị phát hiện khi deploy; IDE hỗ trợ tìm kiếmThêm feature mới phải sửa code + deploy
Dynamic (admin tự nhập code trong DB)Không cần redeploy khi thêm featureTypo gây bug im lặng; không thể validate ở backend; khó audit

Với internal tool ít người dùng, redeploy khi thêm feature là chấp nhận được. Static đảm bảo đúng hơn.

Admin bypass — hai lớp kiểm tra

has_feature() kiểm tra user.get("role") == "admin" trước — trả True trực tiếp, không đọc features list. Lý do: sau khi đổi password hoặc session cache stale, features có thể là [] nhưng admin không bao giờ bị lock out.

UNION semantics cho multi-group

Backend dùng SELECT DISTINCT gf.feature_code ... WHERE gm.staff_id = ? — user thuộc nhiều nhóm tự động nhận union of features. Frontend chỉ nhận list codes, không cần biết nhóm nào cấp code nào.

Feature cache — re-login để refresh

Features được load 1 lần sau login, lưu trong app.storage.user["features"]. Khi admin thay đổi phân quyền nhóm, user cần re-login để thấy hiệu lực.

Tradeoff chấp nhận: internal tool, ít user, thay đổi quyền không thường xuyên. Real-time invalidation sẽ cần WebSocket hoặc polling — over-engineering cho use case này.
Sidebar: ẩn dept group khi tất cả items bị hide

_dept_group() lọc visible_items qua has_feature(). Nếu dept["items"] không rỗng nhưng visible_items rỗng → return sớm (không render header). Tránh user thấy flyout header nhưng click ra không có gì bên trong.

logs.py — thay thế role check bằng feature check

Trước: role not in ("admin", "giam_doc", "pho_giam_doc"). Sau: not has_feature("menu.logs"). Admin vẫn thấy do bypass. GĐ/PGĐ thấy nếu được gán nhóm có menu.logs. Linh hoạt hơn — không hardcode role.

13 Báo cáo dữ liệu thanh toán SWIFT — Phòng Tổng hợp Hoàn thành
Bối cảnh

Phòng Tổng hợp upload file Lệnh đến (IN) và Lệnh đi (OUT) từ hệ thống SWIFT → hệ thống điền vào mẫu báo cáo D00054 của Ngân hàng Nhà nước (template cố định, không được sửa định dạng).

Template path

Lưu tại templates/Phòng Tổng hợp/Báo cáo giao dịch chuyển tiền qua Swift/D00054-*.xlsx. Path được build bằng pathlib.Path trong Python — hoạt động đúng với Unicode trên Windows, không dùng shell để tránh encoding issue.

Xử lý giá trị số
TrườngXử lý
STTLM_AMT (IN) / TOTAL_AMT (OUT)Chia 1000, làm tròn 2 chữ số thập phân → ghi float vào cell
TOTALGhi int
Ô có giá trị 0Ghi None (để trống) thay vì 0 — template không yêu cầu điền 0 tường minh

Ghi float thay vì string "144,55" để row 217 (Tổng cộng) tính đúng. Row 217 không có SUM formula trong template — tính thủ công trong Python sau khi điền xong các rows 20–214.

Dấu phẩy thập phân (theo yêu cầu nghiệp vụ) được xử lý bởi định dạng ô trong template (locale ngân hàng). Không set number_format trong code để đảm bảo không sửa định dạng.
Country matching

Template có 195 quốc gia (rows 20–214, cột C). File IN/OUT có tên quốc gia uppercase trong cột CTHED. Mapping bằng upper().strip() — đủ để match vì cả hai nguồn dùng cùng tên tiếng Anh theo chuẩn SWIFT. Quốc gia không match được → log warning, bỏ qua (không crash).

Sidebar — Nested flyout (cascade 2 cấp)

Cấu trúc sidebar hiện tại chỉ hỗ trợ 1 cấp (dept → items). Đã mở rộng _dept_group() để items có thể là tuple (link trực tiếp) hoặc dict sub-group (nested flyout). CSS thêm class .flyout-group + .sub-flyout — hover trigger giống pattern dept-item hiện có. Không ảnh hưởng các dept khác vì chỉ tonghop có dict sub-group.

Permission model

Backend dùng get_current_staff (bất kỳ user đã đăng nhập). Kiểm soát truy cập bằng feature menu.th_reports gán qua nhóm — phù hợp hơn role check vì nhân viên TH có roles khác nhau (truong_phong, pho_phong) và không có role riêng cho phòng TH.

Period — query param thay vì Form field

period (YYYYMM) truyền qua query string (?period=202605) thay vì Form field. Lý do: api.post_upload_bytes() trong frontend không hỗ trợ data parameter — tránh sửa api_client cho 1 endpoint duy nhất.

14 Fix vòng lặp vô tận home ↔ handovers — user chưa phân nhóm Fix
Root cause

_redirect_if_cv() redirect tất cả chuyen_vien sang /handovers vô điều kiện. Khi CV thuộc phòng TH (hoặc chưa có nhóm quyền), /handovers phát hiện điều kiện bị chặn và redirect ngược về / (= /home) → lại kích hoạt _redirect_if_cv() → vòng vô tận.

dashboard_page() → _redirect_if_cv() → /handovers
                                              ↑         ↓  TH dept check → navigate("/")
                                              └──────────┘
Đánh đổi quan trọng

_redirect_if_cv() dùng ở 2 mục đích khác nhau:

Nơi gọiMục đíchThay đổi
bundles, storage, reports, staff...Chặn CV truy cập trang không phải của họ → redirect /handoversGiữ nguyên

Thay vì sửa _redirect_if_cv() toàn cục (ảnh hưởng tất cả trang), fix inline tại dashboard.py và login.py để chỉ redirect nếu user thực sự có quyền handovers.

  • CV không có feature (chưa phân nhóm, hoặc TH dept): dừng tại /home — không loop
  • Non-CV chưa phân nhóm: vẫn ở /home, sidebar ẩn hết menu (check_features)

15 Single-session enforcement — push-out khi đăng nhập từ thiết bị khác done · 2026-06-09
Quyết định thiết kế

Dùng session_key (UUID) thay vì so sánh IP để detect session bị thay thế. Lý do: NiceGUI là server-side rendering — mọi request từ browser đều đi qua NiceGUI server, nên request.client.host tại FastAPI luôn là 127.0.0.1, không phải IP browser thật.

Cơ chế hoạt động
BướcHành động
Đăng nhậpTạo UUID session_key, lưu vào login_sessions.session_key, nhúng vào JWT payload (sk claim)
Force-login từ máy 2INSERT OR REPLACE ghi đè session_key mới — session cũ của máy 1 bị invalidate

16 Fix IP logging — nhật ký luôn ghi 127.0.0.1 done · 2026-06-09
Root cause

Frontend NiceGUI gửi IP thật qua header X-Client-IP khi login, nhưng backend/api/auth.py đọc request.client.host — đây là IP của NiceGUI process, luôn là 127.0.0.1.

Fix

client_ip = request.headers.get("X-Client-IP") or request.client.host — ưu tiên header do frontend chuyển tiếp.

Chỉ áp dụng cho endpoint login. Các endpoint khác không cần IP thật vì session đã được xác định qua JWT + session_key.
